HotelApp Authentication / Authorization

Kimlik dogrulama ve yetkilendirme akisi. JWT token tabanli, MVC Session ile entegre, email dogrulama ve hesap kilitleme destekli.

Token Tipi

Mimari Ozet

Backend (API): JWT token uretir, dogrular, endpoint'leri [Authorize] ile korur.

Frontend (MVC): Token'i Session'da saklar, ApiService her istekte header'a ekler, Filter'lar ile sayfa erisimini kontrol eder.

02. Kayit Akisi

Kullanici Kayit + Email Dogrulama

1 Kullanici /Auth/Register sayfasini acar
2 Ad, soyad, email, sifre, telefon girer
3 AuthController.Register (POST) -> ApiService -> POST /api/auth/register
4 API: email benzersiz mi kontrol, sifre BCrypt ile hash'le
5 API: IsEmailVerified=false, EmailVerificationToken=GUID olustur
6 API: Dogrulama maili gonder (link icinde token)
7 Kullaniciya "E-postanizi kontrol edin" mesaji gosterilir

Kayit API Degisikligi

Mevcut E01 (register) endpoint'i guncellenir:

  • Kayit sonrasi JWT token donmez (email dogrulanmadan giris yok)
  • Yerine basari mesaji doner: {"message": "Dogrulama maili gonderildi"}
  • IsEmailVerified=false, IsActive=true, EmailVerificationToken=GUID atanir

03. Email Dogrulama Akisi

Mail Linki ile Dogrulama + Otomatik Giris

1 Kullanici mailindeki linki tiklar: /Auth/VerifyEmail?token=abc123
2 AuthController.VerifyEmail -> ApiService -> GET /api/auth/verify-email?token=abc123
3 API: token'i DB'de bul, IsEmailVerified=true yap, token'i sil
4 API: JWT login token'i uret ve dondur
5 MVC: Token'i session'a kaydet (otomatik giris)
6 Kullanici ana sayfaya giris yapmis olarak yonlendirilir

Yeni API Endpoint Gerekli

E42 - GET /api/auth/verify-email?token={token}

  • Anonymous erisim
  • Token gecerli ve eslesen kullanici varsa: IsEmailVerified=true
  • JWT token dondurur (otomatik giris icin)
  • Gecersiz/suresi dolmus token: 400 Bad Request

Email Gonderim Servisi

Gelistirme ortami: Mailtrap (sandbox - gercek mail gitmez, test edilir)

Uretim ortami: Gmail SMTP veya SendGrid

Mail icerigi: "Merhaba {Ad}, hesabinizi dogrulamak icin asagidaki linke tiklayin: {link}"

Link formati: https://localhost:5001/Auth/VerifyEmail?token={guid}

04. Giris Akisi

Standart Giris

1 Kullanici /Auth/Login sayfasini acar
2 Email + sifre + (opsiyonel) "Beni Hatirla" checkbox
3 AuthController.Login (POST) -> ApiService -> POST /api/auth/login
4 API kontrolleri (sirayla):
a) Email kayitli mi? -> 401 "Yanlis email veya sifre"
b) Hesap kilitli mi? (LockoutEndTime > now) -> 403 "Hesap gecici olarak kilitli"
c) Email dogrulanmis mi? (IsEmailVerified) -> 403 "Lutfen emailinizi dogrulayin"
d) Hesap aktif mi? (IsActive) -> 403 "Hesap devre disi"
e) Sifre dogru mu? (BCrypt verify) -> 401 + FailedLoginAttempts++
5 Tum kontroller gecerse: FailedLoginAttempts=0, JWT token uret
6 MVC: Token + kullanici bilgisi session'a kaydedilir
7 returnUrl varsa oraya, yoksa ana sayfaya yonlendir

Hata Senaryolari

  • 401: Yanlis email veya sifre (hangisi yanlis soylenmez - guvenlik)
  • 403 (kilitli): "Hesabiniz gecici olarak kilitlendi. 1 dakika sonra tekrar deneyin."
  • 403 (email): "Lutfen e-posta adresinizi dogrulayin. Yeni dogrulama maili gonder?"
  • 403 (pasif): "Hesabiniz devre disi birakilmistir. Yoneticiyle iletisime gecin."

05. Beni Hatirla Ozelligi

DurumToken SuresiSession/CookieDavranis
Beni Hatirla = OFF60 dakikaSession cookie (tarayici kapaninca silinir)Tarayici kapatilinca oturum duser
Beni Hatirla = ON7 gunPersistent cookie (7 gun gecerli)Tarayici kapatilsa bile 7 gun girisli kalir

Implementasyon

  • Login isteginde "rememberMe: true/false" parametresi API'ye gonderilir
  • API, rememberMe=true ise 7 gunluk token, false ise 60 dakikalik token uretir
  • MVC tarafinda: rememberMe=true ise cookie'nin Expires degeri 7 gun olarak ayarlanir
  • rememberMe=false ise session cookie (Expires yok = tarayici kapaninca silinir)

06. Hesap Kilitleme (Brute Force Koruma)

Basarisiz Giris -> Gecici Kilitleme

1 Kullanici yanlis sifre girer -> FailedLoginAttempts += 1
2 FailedLoginAttempts < 5 -> "Yanlis email veya sifre" mesaji
3 FailedLoginAttempts = 5 -> LockoutEndTime = now + 1 dakika
4 Kilitli iken giris denemesi -> 403 "Hesap kilitli, X saniye bekleyin"
5 1 dakika gecince kilit kalkar, kullanici tekrar deneyebilir
6 Basarili giris -> FailedLoginAttempts = 0, LockoutEndTime = null
ParametreDegerAciklama
MaxFailedAttempts5Maksimum basarisiz deneme sayisi
LockoutDuration1 dakikaKilitleme suresi
ResetOnBasarili girisBasarili giriste sayac sifirlanir

07. Cikis Akisi

Kullanici Cikisi

1 Kullanici navbar'dan "Cikis Yap" tiklar
2 AuthController.Logout cagirilir
3 Session tamamen temizlenir (HttpContext.Session.Clear)
4 Auth cookie silinir
5 Ana sayfaya yonlendirilir

09. MVC Sayfa Koruma (Filters)

AuthFilter

Kontrol: Session'da JWT token var mi?

Yoksa: /Auth/Login?returnUrl={current} sayfasina yonlendir

Varsa: Devam. ApiService token'i header'a ekler.

API 401 donerse: Session temizle, login'e yonlendir

Uygulandigi yerler: Reservations, Reviews, Profile, Booking controller'lari

AdminFilter

Kontrol: Session'daki kullanicinin rolu "Admin" mi?

Degilse: 403 Forbidden sayfasi veya ana sayfaya yonlendir

Ise: Devam, admin layout ile render

Uygulandigi yerler: Admin/ altindaki tum controller'lar

returnUrl Mekanizmasi

Kullanici korunakli sayfaya giris yapmadan erismek isterse, login sayfasina yonlendirilir. Login basarili olunca, orijinal sayfasina geri doner.

Ornek: /Reservations/My -> /Auth/Login?returnUrl=/Reservations/My -> giris -> /Reservations/My
