HotelApp Gorev Dagilimi Plani

Dikey ozellik dilimi (vertical feature slicing) yaklasimi. Her takim uyesi bir ozellik grubunu DB'den frontend'e kadar uctan uca gelistirir. Kickoff toplantisinda grup atamalari netlesti: Grup A = Alper, Grup B = Hilal, Grup C = Sevde.

Neden Dikey Dilimleme?

  • Her takim uyesi DB, Backend (Domain, Infrastructure, API) ve Frontend (MVC) katmanlarinda calisir
  • Kimse sadece "frontend" veya sadece "backend" yapmaz -- herkes tum katmanlari ogrenir
  • Her ozellik grubu bagimsiz gelistirilebilir, birbirini minimum bloklar
  • Kickoff toplantisinda grup atamalari netlesti: Grup A Alper, Grup B Hilal, Grup C Sevde

02. Grup A Kimlik + Yonetim

Sorumlu: Alper. Kullanici kimlik dogrulama, profil yonetimi ve admin yonetim paneli. JWT implementasyonu nedeniyle en karmasik grup.

DB Katmani (4 Tablo)

Users Roles UserRoles Logs

Auth kolonlari (IsEmailVerified, EmailVerificationToken, VerificationTokenExpiry, FailedLoginAttempts, LockoutEndTime) + ilgili Index'ler. Logs tablosu: 10 kolon, 3 Index (Timestamp, Level, UserId), FK -> Users (ON DELETE SET NULL).

Backend servisleri: AuthService (JWT uretimi, BCrypt, email dogrulama), UserService, EmailService (SMTP), LoggerService (Singleton Pattern)

Singleton Logger: ILoggerService (Domain), LogRepository (Infrastructure - Singleton impl), ExceptionLoggingMiddleware (API). Tum controller'lara log cagrilari eklenir (~15 log noktasi).

07. Birlestirme Sureci (Alper)

Alper kendi grubundaki gorevlere ek olarak birlestirme sorumlusudur.

SorumlulukAciklama
PR ReviewHer takim uyesinin Pull Request'ini inceleyip onaylama
Branch MergeTakim branch'lerinden gelen degisiklikleri kontrollu sekilde ana akisa birlestirme
Conflict CozumuMerge conflict durumlarinda karar verme ve cozme
Entegrasyon TestiBirlestirme sonrasi tum akislarin uctan uca calistigini dogrulama
Build KontroluHaftalik olarak tum projenin derlenmesini ve calismasini kontrol etme

Git Branch Stratejisi

  • main: Sadece stabil, calisir ve teslime hazir kod
  • dev: Takimin ortak gelistirme ve entegrasyon branch'i
  • alper-dev: Alper'in gelistirme branch'i (Grup A)
  • hilal-dev: Hilal'in gelistirme branch'i (Grup B)
  • sevde-dev: Sevde'nin gelistirme branch'i (Grup C)
  • Akis: herkes kendi branch'inde calisir, hazir oldugunda dev branch'ine PR acar; test ve kontrol sonrasi uygun surum main'e alinir

Onemli Notlar

  • Grup atamalari tamamlandi: Grup A Alper, Grup B Hilal, Grup C Sevde
  • Kurgu asamasi tamamlandi, proje aktif gelistirme asamasina gecmeye hazir
  • Takvim/sprint hedefleri tarih netlesince ayri olarak planlanacaktir
  • Ortak altyapi ilk hafta icerisinde birlikte tamamlanacaktir
