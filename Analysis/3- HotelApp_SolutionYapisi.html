01. Onion Architecture Nedir?

Onion Architecture, uygulamayı iç içe katmanlardan oluşan bir soğan gibi düşünür. En içteki katman (Domain) hiçbir şeye bağımlı değildir, dış katmanlar iç katmanlara bağımlıdır ama iç katmanlar dış katmanları bilmez. Bu sayede veritabanı teknolojisi değişse bile iş mantığı (business logic) etkilenmez.

Presentation (API)
Infrastructure (Data)
Domain Core

Bağımlılık kuralı: Oklar her zaman dıştan içe doğru gider. Presentation → Infrastructure → Domain. Domain hiçbir katmana bağımlı değildir.

Neden Onion Architecture?

1. Bağımsızlık: Veritabanı değişse (SQL Server → PostgreSQL) sadece Infrastructure katmanı değişir, diğerleri aynı kalır.

2. Test edilebilirlik: Interface'ler sayesinde mock nesnelerle test yazılabilir.

3. Bakım kolaylığı: Her katmanın tek sorumluluğu var (SOLID - Single Responsibility).

4. Takım çalışması: Farklı kişiler farklı katmanlarda çalışabilir, çakışma az olur.

03. Proje Referansları (Bağımlılık Yönü)

Hangi proje hangisine referans veriyor? Bu yapı Onion kuralını uygular:

Okun yönü: "bağımlıdır" anlamına gelir

HotelApp.API → HotelApp.Infrastructure → HotelApp.Domain

HotelApp.Domain: Hiçbir projeye referans vermez. En bağımsız katman.

HotelApp.Infrastructure: Domain'e referans verir. EF Core paketleri burada.

HotelApp.API: Tüm katmanlara referans verir. Dependency Injection burada yapılandırılır (Program.cs).

04. Domain Katmanı (HotelApp.Domain)

Bu Katmanın Görevi

Uygulamanın çekirdeği. Entity'ler (veritabanı tablolarının C# karşılıkları), interface'ler ve DTO'lar burada tanımlanır. Hiçbir dış kütüphaneye bağımlı değildir - saf C# sınıfları. StudentDemo'da Core olarak adlandırılmış, biz de aynı mantığı kullanıyoruz.

Entities (Varlıklar)

Veritabanındaki her tablonun C# sınıf karşılığı. Scaffold komutuyla otomatik üretilir, gerekirse partial class ile genişletilir.

Entities/
Hotel.cs ← Hotels tablosu. Id, Name, City, StarRating, AvgRating...
RoomType.cs ← RoomTypes tablosu. Id, Name, MaxGuests
HotelRoom.cs ← HotelRooms ara tablosu. HotelId, RoomTypeId, PricePerNight, TotalRooms
User.cs ← Users tablosu. Id, FirstName, Email, PasswordHash
Role.cs ← Roles tablosu. Id, Name
UserRole.cs ← UserRoles ara tablosu. UserId, RoleId
Reservation.cs ← Reservations tablosu. CheckIn, CheckOut, Status, TotalPrice
Review.cs ← Reviews tablosu. Rating, Comment
HotelImage.cs ← HotelImages tablosu. ImageUrl, IsMain
Amenity.cs ← Amenities tablosu. Name, Icon
HotelAmenity.cs ← HotelAmenities ara tablosu. HotelId, AmenityId
LogEntry.cs ← Logs tablosu. Id, Timestamp, Level, Message, UserId, Controller, Action Logger Singleton

Scaffold komutu ile üretim: Bu entity'ler SQL Server'daki tablolardan dotnet ef dbcontext scaffold komutuyla otomatik üretilir. Üretilen dosyalar bu klasöre taşınır. LogEntry.cs Singleton Logger pattern için manuel oluşturulur.

DTOs (Data Transfer Objects)

API'den dışarıya veri gönderirken ve dışarıdan veri alırken kullanılan sınıflar. Entity'nin tamamını dışarıya açmak güvenlik riski oluşturur (örneğin PasswordHash görünmemeli). DTO'lar sadece gerekli alanları içerir.

DTOs/
── Hotel ──
HotelDto.cs ← Otel listeleme/detay için (Id, Name, City, StarRating, AvgRating)
HotelCreateDto.cs ← Yeni otel eklerken alınacak alanlar
HotelUpdateDto.cs ← Otel güncellerken alınacak alanlar

── Room ──
RoomTypeDto.cs ← Oda tipi bilgisi
HotelRoomDto.cs ← Otel-oda eşleşmesi + fiyat bilgisi
AvailableRoomDto.cs ← Müsait oda arama sonucu

── User ──
UserDto.cs ← Kullanıcı bilgisi (PasswordHash HARİÇ)
UserRegisterDto.cs ← Kayıt formu alanları
UserLoginDto.cs ← Giriş formu (Email + Password)
LoginResponseDto.cs ← Giriş sonucu (Token + kullanıcı bilgisi)

── Reservation ──
ReservationDto.cs ← Rezervasyon detayı
ReservationCreateDto.cs ← Yeni rezervasyon oluşturma alanları

── Review ──
ReviewDto.cs ← Yorum bilgisi
ReviewCreateDto.cs ← Yeni yorum oluşturma alanları

── Log ──
LogDto.cs ← Admin log görüntüleme (Id, Timestamp, Level, Message, UserEmail, Controller, Action) Logger Singleton

Interfaces (Arayüzler)

Repository ve Service sözleşmeleri. "Ne yapılacağını" tanımlar, "nasıl yapılacağını" tanımlamaz. StudentDemo'daki IRepository, IUnitOfWork pattern'inin aynısı:

Interfaces/
IRepository<T>.cs ← Generic CRUD: GetAll, GetById, Find, Add, Update, Delete, Exists
StudentDemo ile aynı

IUnitOfWork.cs ← Tüm repository'lere erişim + SaveChanges + Transaction
StudentDemo ile aynı pattern, daha fazla repository property

IHotelRepository.cs ← Hotel'e özel sorgular (şehre göre, yıldıza göre)
IRoomTypeRepository.cs
IHotelRoomRepository.cs ← Müsait oda arama sorgusu
IUserRepository.cs ← Email ile kullanıcı bulma
IReservationRepository.cs ← Tarih çakışması kontrolü
IReviewRepository.cs ← Otele göre yorumlar
IAmenityRepository.cs

İş mantığı sözleşmeleri. Controller doğrudan repository çağırmaz, service üzerinden gider. StudentDemo'daki IBookService/IAuthorService pattern'i:

05. Infrastructure Katmanı (HotelApp.Infrastructure)

Bu Katmanın Görevi

Veritabanı erişiminin gerçekleştiği katman. EF Core DbContext, Repository implementasyonları ve UnitOfWork burada bulunur. Domain katmanındaki interface'lerin somut (concrete) implementasyonlarını içerir. StudentDemo'daki Data katmanının karşılığı.

Context

Scaffold komutuyla üretilen DbContext sınıfı. Tüm entity'lerin DbSet tanımlarını ve tablo yapılandırmalarını (OnModelCreating) içerir.

Context/
HotelAppDbContext.cs ← Scaffold ile üretilir. 12 DbSet, ilişki yapılandırmaları (Logs dahil)
DB First - Scaffold

Scaffold komutu:

dotnet ef dbcontext scaffold "Server=.;Database=HotelAppDb;Trusted_Connection=True;TrustServerCertificate=True" Microsoft.EntityFrameworkCore.SqlServer -o Models --context HotelAppDbContext --context-dir Context

Bu komut çalıştırıldığında Entity sınıfları ve DbContext otomatik üretilir. Entity'ler Domain/Entities klasörüne, DbContext Infrastructure/Context klasörüne taşınır.

Repositories (Repository Implementasyonları)

Domain katmanındaki interface'lerin somut implementasyonları. StudentDemo'daki abstract Repository sınıfı ve entity-specific repository pattern'inin aynısı:

Repositories/
Repository<T>.cs ← Abstract generic repository (GetAll, GetById, Add, Update, Delete)
StudentDemo Repository.cs ile aynı

HotelRepository.cs ← : Repository<Hotel>, IHotelRepository
← GetByCityAsync(), GetByStarRatingAsync(), SearchAsync()
RoomTypeRepository.cs ← : Repository<RoomType>, IRoomTypeRepository
HotelRoomRepository.cs ← : Repository<HotelRoom>, IHotelRoomRepository
← GetAvailableRoomsAsync() - müsaitlik hesaplaması
UserRepository.cs ← : Repository<User>, IUserRepository
← GetByEmailAsync() - giriş için email ile arama
ReservationRepository.cs ← : Repository<Reservation>, IReservationRepository
← HasConflictAsync() - tarih çakışması kontrolü
ReviewRepository.cs ← : Repository<Review>, IReviewRepository
← GetByHotelIdAsync() - otele göre yorumlar
AmenityRepository.cs ← : Repository<Amenity>, IAmenityRepository

LogRepository.cs ← : ILoggerService (Singleton implementasyonu)
Singleton Pattern
← Private constructor + Lazy<LogRepository> (thread-safe)
← Initialize(connectionString) ile Program.cs'den başlatılır
← Her log yazımında kısa ömürlü DbContext oluşturur

UnitOfWork

UnitOfWork.cs ← IUnitOfWork implementasyonu. Tüm repository'lere tek noktadan erişim + transaction yönetimi
StudentDemo UnitOfWork.cs ile aynı pattern

StudentDemo'dan fark: IUnitOfWork içinde Books ve Authors yerine Hotels, Rooms, Users, Reservations, Reviews, Amenities property'leri olacak.

06. Presentation Katmanı (HotelApp.API)

Bu Katmanın Görevi

Dış dünyayla iletişim kuran katman. HTTP isteklerini karşılayan Controller'lar, Dependency Injection yapılandırması (Program.cs), Authentication/Authorization middleware ve Swagger API dökümantasyonu burada bulunur.

Controllers

Controllers/
HotelsController.cs ← GET /api/hotels, GET /api/hotels/{id}, POST, PUT, DELETE
RoomTypesController.cs ← GET /api/roomtypes
HotelRoomsController.cs ← GET /api/hotels/{id}/rooms, POST müsait oda arama
AuthController.cs ← POST /api/auth/register, POST /api/auth/login
ReservationsController.cs ← POST /api/reservations, GET /api/reservations/my
ReviewsController.cs ← POST /api/reviews, GET /api/hotels/{id}/reviews
AmenitiesController.cs ← GET /api/amenities
AdminController.cs ← Admin-only işlemler (istatistik, yönetim)

Middleware

Middleware/
ExceptionLoggingMiddleware.cs ← Global hata yakalama ve loglama Logger Singleton
← Tüm yakalanmamış exception'ları yakalar
← LogError ile hata detayını (stack trace) kaydeder
← İstemciye 500 Internal Server Error döner

Program.cs

Uygulamanın giriş noktası. Tüm servislerin Dependency Injection ile kaydedildiği yer:

Program.cs
← DbContext kaydı (SQL Server connection string)
← Repository DI: builder.Services.AddScoped<IHotelRepository, HotelRepository>()
← Service DI: builder.Services.AddScoped<IHotelService, HotelService>()
← UnitOfWork DI: builder.Services.AddScoped<IUnitOfWork, UnitOfWork>()
← Logger Singleton başlatma: LogRepository.Initialize(connectionString)
← Logger DI: builder.Services.AddSingleton<ILoggerService>(LogRepository.Instance)
← JWT Authentication yapılandırması
← CORS ayarları (frontend ile iletişim için)
← app.UseMiddleware<ExceptionLoggingMiddleware>()
← Swagger yapılandırması

Diğer Dosyalar

appsettings.json ← ConnectionString, JWT ayarları
appsettings.Development.json ← Geliştirme ortamı ayarları
Dockerfile ← Docker imajı oluşturma
docker-compose.yml ← API + SQL Server birlikte çalıştırma
