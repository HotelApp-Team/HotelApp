HotelApp Risk ve Bagimliliklar

Proje gorevleri arasindaki bagimliliklari, tikanma noktalarini, teknik riskleri ve azaltma stratejilerini icerir. Gorev dagilimi ve sprint plani bu analize dayanarak olusturulacaktir.

t!-- BACKEND BAGIMLILIKLARI -->

01. Backend Gelistirme Sirasi

Backend katmanlari Onion Architecture sirasina gore birbirine bagimlidir. Asagidaki sira bozulamaz.

1 Veritabani (SQL Server)

CREATE TABLE scripti (11 tablo) SP: sp_SearchAvailableRooms SP: sp_MakeReservation View: vw_HotelSummary, vw_ReservationDetails Trigger: trg_UpdateHotelRating Index'ler Seed data (test verileri)

2 Domain Katmani

Entity'ler (Scaffold ile uretilir) Repository interface'leri (IHotelRepository vb.) Service interface'leri DTO'lar Service implementasyonlari Validation JWT Token servisi

3 Infrastructure Katmani

DbContext (Scaffold) Repository implementasyonlari Email servisi (SMTP)

4 Presentation (Web API)

Program.cs (DI, JWT config, CORS) AuthController (E01-E03, E42-E43) HotelsController (E04-E10) Diger controller'lar

Tikanma Noktasi

DB + Scaffold + Domain olmadan hicbir backend kodu yazilamaz. Bu adim projenin en kritik baslangic noktasidir. DB scripti hazir olmadan takim beklemeye gecer.

t!-- FRONTEND BAGIMLILIKLARI -->

02. Frontend (MVC) Gelistirme Sirasi

1 MVC Altyapi (Herkesten Once)

MVC proje olusturma ApiService (HttpClient wrapper) _Layout.cshtml (Public) _AdminLayout.cshtml appsettings.json (API URL) Bootstrap entegrasyonu

2 Auth Sayfalari (Layout'tan Sonra)

Login sayfasi Register sayfasi AuthFilter + AdminFilter _LoginPartial.cshtml

3 Public Sayfalar (Auth'tan Sonra Bagimsiz)

Ana Sayfa Arama Sonuclari Otel Detay Partial View'lar (_HotelCard, _StarRating vb.) Statik sayfalar (Hakkimizda, Iletisim, SSS)

4 User Sayfalari (Auth Calismali)

Rezervasyon modal (Otel Detay icinde) Rezervasyonlarim + Detay Yorumlarim Profil

5 Admin Sayfalari (AdminFilter Calismali)

Dashboard Otel Yonetimi + Duzenleme Oda Tipi / Olanak Yonetimi Rezervasyon / Kullanici Yonetimi

t!-- KRITIK YOL -->

04. Kritik Yol (Critical Path)

Projenin tamamlanmasi icin en uzun bagimlliik zinciri. Bu zincirdeki herhangi bir gecikme tum projeyi geciktirir.

Kritik Yol Zinciri

SQL Script -> Scaffold -> Domain -> Repository -> Service -> JWT Setup -> AuthController -> Auth Sayfalar -> Rezervasyon Akisi

Neden kritik? Rezervasyon yapabilmek icin kullanicinin giris yapmis olmasi, giris icin auth'un calismasi, auth icin JWT'nin ayarlanmis olmasi, JWT icin entity'lerin olmasi, entity'ler icin DB'nin hazir olmasi gerekir.

t!-- KAPSAM RISKLERI -->

07. Kapsam Riskleri

MVP'den Cikmak (Scope Creep)

Risk: "Su ozellik de olsa guzel olur" diyerek kapsami genisletmek.

Ornekler:

  • Harita entegrasyonu (Google Maps)
  • Odeme sistemi (iyzico/stripe)
  • Coklu dil destegi
  • Anlik bildirimler (SignalR)

Strateji: Bu ozellikler "Nice to Have" listesinde tutulur. Temel islevler tamamlanmadan baslanmaz.

Yetersiz Test Verisi

Risk: DB'de yeterli test verisi olmadigi icin sayfalarin bos gorunmesi, sayfalama/filtrelemenin test edilememesi.

Strateji: SQL seed scripti ile en az 10 otel, 5 oda tipi, 20 rezervasyon, 30 yorum girilecek. Seed data gercekci olacak.

t!-- AZALTMA PLANI -->

08. Risk Azaltma Plani

Oncelik 1: Kritik Yolu Acmak

  • Ilk gun: SQL script + Solution + Scaffold takim tarafindan birlikte tamamlanir
  • Ilk hafta: JWT + AuthController + en az 1 CRUD controller calisir halde olur
  • Bu adim tamamlanmadan frontend kodlamasina baslanmaz (layout haric)

Oncelik 2: Paralel Calisma Imkani Olusturmak

  • Backend ve frontend gorevleri esit olarak dagitilir, herkes her katmanda calisir
  • Backend API Swagger ile dokumanlenir, tum takim endpoint'leri gorup test edebilir
  • Gorevler birbirini bloklamayacak sekilde dagitilir

Oncelik 3: Erken Test ve Surekli Entegrasyon

  • Her tamamlanan endpoint Swagger/Postman ile test edilir
  • Her tamamlanan sayfa gercek API'ye baglanarak test edilir
  • Haftalik build kontrolu: tum proje derlenmeli ve calisir halde olmali
  • PR (Pull Request) ile code review zorunlu

Yedek Plan: Email Servisi Calismassa

  • Email dogrulama opsiyonel olarak devre disi birakilabilir (IsEmailVerified=true default)
  • Kayit -> dogrudan giris akisina donulebilir (orjinal E01 davranisi)
  • Email servisi sonradan eklenir, MVP bloklanmaz
